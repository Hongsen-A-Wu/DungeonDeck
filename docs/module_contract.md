
# Dungeon Deck：模块接口约定（初始草案）

## 1. 场景 ID（3 位）

所有场景使用 3 位二进制数表示：

- `0`：Town（城镇）
- `1`：House 1（房屋 1）
- `2`：House 2（房屋 2）
- `3`：Dungeon（地牢）
- `4`：Battle（战斗）
- `5`：Victory（胜利）
- `6`：Defeat（失败）

## 2. 探索模式坐标系统

地图采用格子系统（Tile Map）：

- 地图宽度：20 个格子
- 地图高度：15 个格子
- `player_x[4:0]`：玩家的水平坐标，范围为 `0~19`
- `player_y[4:0]`：玩家的垂直坐标，范围为 `0~14`

对于 **160×120 的逻辑画布（Logical Canvas）**：

- 每个地图格子占据 `8×8` 个逻辑像素。
- 整张地图共包含 `20×15` 个格子。
- 使用课程提供的 `160×120` 帧缓冲区（Framebuffer）时，在 `640×480` 的物理 VGA 显示模式下，每个逻辑像素在水平和垂直方向均放大 4 倍。
- 因此，每个 `8×8` 的逻辑格子最终在显示器上占据 `32×32` 个物理像素。

### 临时交互位置

以下位置为临时设定，后续需要根据队友设计的地图进行调整：

- House 1（房屋 1）入口：`(4,3)`
- House 2（房屋 2）入口：`(15,3)`
- Dungeon（地牢）入口：`(10,12)`
- Dungeon Enemy（地牢敌人）：`(10,5)`

## 3. 输入事件（Input Events）

所有输入事件均使用**持续一个时钟周期的脉冲信号（One-clock Pulses）**。

统一定义以下输入信号：

- `move_up`：向上移动
- `move_down`：向下移动
- `move_left`：向左移动
- `move_right`：向右移动
- `confirm`：确认或交互
- `back`：返回或退出

### 输入处理规则

- 每个输入事件只持续一个时钟周期。
- 每个有效脉冲触发一次对应操作。
- 不应直接将持续按住的按键解释为连续移动指令。
- 如果需要实现长按连续移动，必须额外设计明确的按键重复机制（Key Repeat）或移动时钟节拍（Movement Tick）。

## 4. 渲染模块接口划分（Rendering Boundary）

游戏逻辑模块与图形渲染模块必须保持分离。

### 游戏逻辑模块（Game Logic）

游戏逻辑模块负责管理以下状态和数据：

- `scene`：当前游戏场景
- `player_x`：玩家水平坐标
- `player_y`：玩家垂直坐标
- `health`：玩家生命值
- `energy`：玩家当前能量
- `selected_card`：当前选中的卡牌

游戏逻辑模块负责更新这些数据，不直接控制 VGA 像素绘制。

### 图形渲染模块（Rendering）

渲染模块负责：

- 接收游戏逻辑模块提供的状态信号。
- 根据 `scene` 选择对应的游戏画面。
- 根据 `player_x` 和 `player_y` 确定玩家的显示位置。
- 根据生命值、能量和卡牌状态绘制对应的 UI。
- 控制 VGA 图像绘制，不负责修改游戏逻辑状态。

### VGA 显示实现方式

在开始设计角色精灵图（Sprite）之前，必须与负责 VGA 的队友统一帧缓冲区（Framebuffer）的实现方式。

需要在以下方案中确定一种：

1. **VGA Adapter 写入接口（Write Interface）**
   - 通过 VGA Adapter 提供的接口向帧缓冲区写入像素数据。
   - 由 VGA Adapter 负责读取帧缓冲区并输出 VGA 信号。

2. **直接像素扫描（Direct Pixel Scan）**
   - 根据当前扫描位置实时计算需要显示的像素颜色。
   - 不依赖通过 VGA Adapter 写接口逐点更新画面的方式。

**注意：必须先确定 VGA 渲染架构，再开始设计 Sprite 和地图绘制逻辑，以避免后续模块接口不兼容。**
